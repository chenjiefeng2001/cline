## Synopsis

```bash
cline [options] [command] [prompt]
```

| `--max-tool-calls <count>` | Ceiling on tool calls per run (default: unlimited). Distinct from `--max-iterations`, which counts model round-trips: one turn can issue many tool calls, so the iteration cap does not bound them. Reaching it ends the run as `tool_calls_exhausted` |

| `--sandbox-network` | Let sandboxed shell commands reach the network (implies `--sandbox`). Also removes loopback access for sandboxed processes |
| `--hooks-dir <path>` | Directory path to additional hooks for runtime hook injection (default: `~/.cline/hooks`) |
| `--acp` | Run in Agent Client Protocol (ACP) mode for editor integration |
| `-i, --tui` | Open the terminal user interface (TUI) for interactive sessions |

## Commands

### `cline` (default)

Start a task or enter interactive mode.

```bash
cline
cline "your prompt here"
cline "Run tests and fix failures"
echo "prompt" | cline
```

### `auth [options] [provider]`

Configure authentication with an AI provider.

```bash
cline auth
```

### `config [options]`

Show current configuration.

```bash
cline config
```

### `connect [options] [adapter]`

Connect to messaging platforms. See [Connectors](/cli/connectors).

```bash
cline connect
cline connect [adapter]
```

### `mcp`

Manage MCP servers. See [MCP](/mcp/mcp-overview).

```bash
cline mcp
```

### `dev`

Developer tools and utilities.

```bash
cline dev
```

### `doctor`

Diagnose and fix configuration issues.

```bash
cline doctor
```

### `history|h [options]`

List session history or manage saved sessions.

```bash
cline history
cline h
```

### `hook`

Handle a hook payload from stdin.

```bash
cat payload.json | cline hook
```

### `plugin`

Manage Cline plugins. Install plugins from file URLs, npm, git repositories, or local paths. See [Plugins](/customization/plugins) for full details and the plugin manifest format.

```bash
cline plugin install <source>  # Install a plugin
cline plugin i <source>        # Shorthand alias
```

| Option | Description |
|--------|-------------|
| `--npm` | Treat source as an npm package |
| `--git` | Treat source as a git repository |
| `--force` | Replace an existing install for the same source |
| `--json` | Output result as JSON |
| `--cwd <path>` | Install to `<path>/.cline/plugins` instead of the global directory |

Try it with the [TypeScript Navigation Plugin](https://github.com/cline/typescript-lsp-plugin):

```bash
cline plugin install https://github.com/cline/typescript-lsp-plugin.git
```

### `schedule`

Manage scheduled agents. See [Scheduling](/cli/scheduling).

```bash
cline schedule
```

### `hub`

Manage the local hub daemon.

```bash
cline hub
```

### `update [options]`

Check for updates and install if available.

```bash
cline update
```

### `version`

Show Cline CLI version number.

```bash
cline version
cline -V
```

### `kanban`

Launch the kanban app and exit.

```bash
cline kanban
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `CLINE_DATA_DIR` | Custom configuration directory (replaces `~/.cline/data/`) |
| `CLINE_HUB_ADDRESS` | Override hub address (default: `127.0.0.1:25463`) |
| `CLINE_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `CLINE_SANDBOX_DATA_DIR` | Directory for isolated local state (set by `--data-dir`) |
| `CLINE_SANDBOX` | Set to `1` to enable isolated local state, as `--data-dir` does. **Not** OS process isolation — see `CLINE_PROCESS_SANDBOX` |
| `CLINE_PROCESS_SANDBOX` | ACP sessions only: start with OS process isolation on (`1`/`true`) |
| `CLINE_PROCESS_SANDBOX_NETWORK` | ACP sessions only: allow sandboxed commands to reach the network |
| `CLINE_HOOKS_DIR` | Additional hooks directory |
| `CLINE_BUILD_ENV` | Set to `development` for debug features |
| `CLINE_DEBUG_PORT_BASE` | Base port for Node.js inspector |
| `CLINE_COMMAND_PERMISSIONS` | JSON policy restricting shell commands (see below) |
| `CLINE_MAX_ITERATIONS` | Iteration ceiling for ACP sessions, which have no flag parser (default: `50`) |
| `CLINE_MAX_BUDGET_USD` | Spend ceiling in USD for ACP sessions (default: `5`) |
| `CLINE_CLIENT_USER_AGENT` | Replace the `User-Agent` sent to Cline's gateway and the Codex backend |
| `CLINE_CLIENT_TYPE` | Replace the `X-CLIENT-TYPE` client identity |
| `CLINE_CLIENT_TITLE` | Replace the `X-Title` header |
| `CLINE_CLIENT_REFERER` | Replace the `HTTP-Referer` header |
| `CLINE_CODEX_ORIGINATOR` | Replace the `originator` sent to the Codex backend |

### Run guardrails

`--max-iterations`, `--max-budget-usd`, `--max-parallel-tool-calls`,
`--max-tool-calls` and `--max-subagent-depth` apply to one-shot and interactive
runs. ACP mode has no flags, so it reads the two spend/iteration values from
`CLINE_MAX_ITERATIONS` and `CLINE_MAX_BUDGET_USD`, which default to the same 50
and 5. It has no env equivalent for the tool-call or nesting ceilings: those are
set through the session's config options, which an editor client can change, or by
`CLINE_PROCESS_SANDBOX` for isolation.

A value that is not a usable positive number — zero, negative, `NaN`, or blank —
falls back to the default rather than removing the ceiling, so a typo in an
environment variable cannot quietly remove a limit. Two deliberate exceptions:
`--max-tool-calls` requires `>= 1` (there is no `0 = unlimited` on the CLI, so a
typo landing on `0` is rejected instead of read as "no ceiling"), and
`--max-subagent-depth` accepts `0` because it is meaningful there — `0` forbids
delegation entirely, whereas omitting the flag leaves the default of `1`.

### OS process sandbox

`--sandbox` wraps every shell command in the platform's process sandbox — Seatbelt
on macOS, bubblewrap on Linux — confining writes to the workspace and denying
network. `--sandbox-network` re-permits network; note this also removes loopback
access for sandboxed processes.

The sandbox is **fail-closed**: where no backend is available, commands fail rather
than running unsandboxed. It therefore has no Windows support, and enabling it on a
machine without `bwrap` installed breaks shell commands instead of degrading
quietly. That is deliberate — a sandbox that silently does nothing is worse than
one that is visibly absent — but it is why the default is off.

This is unrelated to `--data-dir`, which only relocates local state. The two were
once both called "sandbox mode", which is why the CLI's internal field is now
`isolatedState`.

### CLINE_COMMAND_PERMISSIONS

Restrict which shell commands the agent can execute:

```bash
export CLINE_COMMAND_PERMISSIONS='{"allow": ["npm *", "git *"], "deny": ["rm -rf *", "sudo *"]}'
```

| Field | Type | Description |
|-------|------|-------------|
| `allow` | `string[]` | Glob patterns for allowed commands. If set, only matching commands are permitted. |
| `deny` | `string[]` | Glob patterns for denied commands. Deny rules always take precedence. |
| `allowRedirects` | `boolean` | Whether to allow shell redirects (`>`, `>>`, `<`). Default: `false`. |

## JSON Output Format

When using `--json`, each message is a JSON object on its own line:

```json
{"type": "say", "text": "I'll create the file now.", "ts": 1760501486669, "say": "text"}
```

| Field | Type | Description |
|-------|------|-------------|
| `type` | `"ask"` or `"say"` | Message category |
| `text` | `string` | Message content |
| `ts` | `number` | Unix timestamp in milliseconds |
| `say` | `string` | Subtype when `type` is `"say"` |
| `ask` | `string` | Subtype when `type` is `"ask"` |
| `reasoning` | `string` | Model reasoning (if available) |
| `partial` | `boolean` | `true` while streaming |

```
  data/
    settings/

  rules/                         # Project rules
  skills/                        # Project skills
  hooks/                         # Lifecycle hooks
  plugins/                       # Project plugins
  mcp.json                       # MCP server config
  agents.yaml                    # Agent definitions
```
